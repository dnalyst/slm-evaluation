# Small Language Model Evaluation

An exploratory, reproducible A/B evaluation of **Qwen/Qwen2.5-0.5B-Instruct**, testing whether a concise system instruction affects response quality and instruction following on ten fixed prompts.

## Key finding
The provisional human-review mean was **5.4/8 for both conditions**. The system condition scored higher on instruction following (1.3 vs 1.0 out of 2), but lower on factual correctness (1.3 vs 1.6). Thirteen of twenty primary responses reached the generation token cap. These small-sample results **do not establish a general benefit** from system prompting.

## Repository contents
- `notebooks/SLM_Evaluation_Final.ipynb`: Colab experiment, automated checks, charts and export
- `data/`: original generations, test cases, runtime metadata, operational metrics and repeatability outputs
- `reports/final_evaluation_report.md`: final interpretation and limitations
- `reports/human_review_provisional.csv`: single-reviewer, provisional rubric scores for the 20 primary responses
- `reports/review_summary.csv` and `reports/paired_score_comparison.csv`: audit summaries
- `figures/`: operational charts regenerated from the bundled primary raw results

## Reproduce
1. Open `notebooks/SLM_Evaluation_Final.ipynb` in Google Colab, preferably with a T4 GPU.
2. Run the cells in order. The notebook installs its dependencies and downloads the public model.
3. The notebook writes fresh generations and a new output ZIP. Stochastic generation, package updates, and hardware differences can change results.
4. The provided `data/` and `reports/` describe the **original recorded run**, not any later rerun. The separately completed provisional human audit is not automatically regenerated by the notebook.

## Method at a glance
Ten prompts, two conditions, 20 primary responses plus six additional system-condition repeats for three prompts; temperature 0.2, top_p 0.9, max_new_tokens 160, paired primary seeds. Recorded run: Tesla T4. Human review: factual correctness, relevance/completeness, instruction following, clarity (0–2 each).

See the [full report](reports/final_evaluation_report.md) for findings, scoring caveats, and limitations.


## Interactive evaluation dashboard

Run with `streamlit run app.py` after `pip install -r requirements.txt`. The dashboard loads saved CSV files and **does not** load the Qwen model or require a GPU. It compares primary outputs, latency, token cap hits, provisional human scores, and individual response texts.

**Provenance and metric consistency:** The raw generation CSV and JSONL contain the same 26 recorded generations. The 20 primary response texts match the earlier reviewed package, while latency measurements differ between exports. For consistency, the operational summary, report and figures in this repository use latency values recalculated from the bundled `data/raw_generation_results.csv`, filtering to `repeat_index == 1` (10 primary outputs per condition). The separate human review is keyed by test ID and condition; it remains a provisional single-reviewer assessment, not an automated score. The dashboard does not generate new experiment results.

**Deployment:** Set `app.py` as the Streamlit entrypoint. Do not install PyTorch or Transformers for this dashboard; model inference is intentionally separate.
